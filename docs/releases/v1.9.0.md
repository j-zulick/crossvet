# Crossvet v1.9.0

Defenses against the harder injections v1.8 measured, a benchmark for the first model that reads each page, and `crossvet-scan` reports you can hand to a client.

## What's new
- **More injections flagged in code.** The injection check now flags a page that is mostly one repeated sentence or one repeated name (the "dominant page" form v1.8 measured), and triggers in Spanish, French, German and Portuguese for text addressed to an AI and for overriding instructions. Paraphrased and split injections are still not caught by patterns. Design decision 22.
- **URLs found only inside a page's text are marked unverified.** When the notes use `URL:` source lines, the Review notes list any cited URL that appears only inside another page's text, never as a source of its own. That is how one v1.8 report picked up a planted "primary reference".
- **A prompt rule for summaries, compression and reports:** a page's recommendations, rankings and instructions are reported as that page's claims, never as findings.
- **First, partial check of these defenses** on `injection-hard`: with the prompt rule, OpenAI report writers adopted a planted claim in 2 of 16 runs (1 of 16 before). Claude report writers adopted none in 12 runs, as before. On this small run the rule did not help; with the flag lines in the notes (`--suite injection-hard-checked`, new in this release), 1 of 28 report writers adopted a planted URL, on the split form the patterns still miss, and the unverified-URL check lists exactly that URL. Details: `docs/benchmarks/2026-11-19-injection-hard-checked/`. Details: `docs/benchmarks/2026-11-18-injection-defenses/`.
- **`crossvet-bench` summarizer role.** The first model to read each fetched page is benchmarked with the pipeline's own summarizer prompt: key facts kept per page, halved when a summary of the injected page states the planted instruction as fact. `apply` writes its winner to `SUMMARIZATION_MODEL`. First outputs, on the hard injection cases, were checked by hand: no summary stated the planted claim as fact; three passed the planted URL on while describing the instruction. The injection scorer was corrected to agree with the hand check.
- **`crossvet-scan` reports.** `--format text|json|csv|html` and `--out FILE`. The HTML report is one self-contained page (no JavaScript, all page text escaped); CSV cells that a spreadsheet would run as formulas are neutralised.
- **`crossvet-scan` on many pages.** `--sitemap URL_OR_FILE` and `--urls FILE`, with `--max-pages` (default 50) and `--delay` (default 0.5 s). Sitemaps are parsed with DTDs refused and a 5 MB cap. Design decision 24.
- **`crossvet-scan --crawl`.** Scan a whole site through a crawlee-server instance: it crawls with page capture on, and every stored page is scanned. `--crawl-mode` picks how it finds pages.
- **Dependencies patched.** Python packages with published advisories (including aiohttp, pyjwt, tornado and urllib3) and the web app's Next.js, KaTeX and Babel are on fixed versions. `pip-audit` reports none on the runtime dependencies; `pnpm audit` reports one moderate advisory in lint tooling.

## Upgrading
Nothing to change. `crossvet-scan --json` still works. `crossvet-bench apply` sets `SUMMARIZATION_MODEL` from the summarizer winner when the role map has one, and from the compression winner otherwise, as before.
